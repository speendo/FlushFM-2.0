# US-0047: Light Sensor — Attenuation, Exponential Filter, and Reading Interval

> **Status:** Done | **Priority:** High | **Created:** 2026-06-07 | **Depends on:** US-0045

## User Story
As a **developer**, I want **the `LightSensor` to produce a stable, low-noise reading via a configurable exponential filter, a user-adjustable ADC attenuation range, and a non-blocking sample interval**, so that **the light sensor output is reliable for state transitions and the board can be calibrated for different lighting environments**.

## Acceptance Criteria

### Attenuation Configuration
- [x] `setAttenuation(float volts)` sets the ADC maximum input range for the light sensor pin only (`analogSetPinAttenuation`). Accepted values: `1.1`, `1.5`, `2.2`, `3.3` (float, matched with epsilon). Rejects all other values.
- [x] `getAttenuation() const` returns the current attenuation as a `float` (volts).
- [x] Compile-time default: `#define LIGHT_SENSOR_DEFAULT_ATTENUATION 3.3f` (0–3.3V range, matches TEMT6000 VCC).
- [x] `begin()` applies the stored attenuation to the pin. Calling `setAttenuation()` at runtime re-applies it to the pin immediately (no restart required).
- [x] Attenuation is pin-specific — does not affect any other ADC pin on the system.

### Exponential Filter
- [x] `readFiltered()` returns the current exponentially smoothed value. Internally samples a single `analogRead()` only when the sample interval has elapsed; returns the cached filtered value otherwise.
- [x] Fixed-point filter with configurable shift factor: `filteredAccum = filteredAccum - (filteredAccum >> shift) + (raw << shift)`.
- [x] `setFilterShift(uint8_t shift)` — accepted range 1–6. Each increment doubles the effective smoothing window. Response times at the default 20 ms interval: shift 1 (τ≈0.04s, 95%≈0.12s), shift 2 (τ≈0.08s, 95%≈0.24s), shift 3 (τ≈0.16s, 95%≈0.48s), shift 4 (τ≈0.32s, 95%≈0.96s), shift 5 (τ≈0.64s, 95%≈1.9s), shift 6 (τ≈1.28s, 95%≈3.8s). Compile-time default `#define LIGHT_SENSOR_FILTER_SHIFT 2` (response in under 0.25s while still smoothing noise).
- [x] `getFilterShift() const` returns the current shift value.
- [x] `readFiltered()` seeds itself on the first call with the current `analogRead()` value (scaled) so it starts at the ambient level immediately — no ramp-up from zero.

### Raw Reading Interval
- [x] `setRawReadingIntervalMs(uint16_t ms)` — sets how often a new raw ADC reading is taken. Default `#define LIGHT_SENSOR_DEFAULT_RAW_READING_INTERVAL_MS 20`. At 20 ms with shift 2: τ≈0.08s, 95%≈0.24s — near-instant response to room light changes.
- [x] `getRawReadingIntervalMs() const` returns the current interval.

### `readZone()` and `readState()` Use Filtered Values
- [x] `readZone()` internally calls `readFiltered()` instead of `readRaw()` — the hysteresis thresholds are compared against the smoothed reading.
- [x] `readState()` internally uses the filtered-based `readZone()`.
- [x] Both `readZone()` and `readState()` become non-`const` (since `readFiltered()` modifies internal filter state). The `mutable` qualifier on `latchedState_` is removed.

### All `#define` Constants Documented
- [x] Every `#define` constant has a `///` doc comment explaining what it controls and the trade-off (e.g. shift values: 1 = fastest but noisy, 3+ = heavy smoothing for slow ambient changes).

### CLI Updates (Debug-Only)
- [x] `light atten <volts>` — sets attenuation (e.g. `light atten 3.3`). Accepts only `1.1`, `1.5`, `2.2`, `3.3`.
- [x] `light interval <ms>` — sets the raw reading interval in milliseconds.
- [x] `light shift <1-6>` — sets the filter shift factor (e.g. `light shift 2`).
- [x] `light status` — updated to print `readFiltered()` as primary value, plus `readRaw()` for comparison, plus current attenuation, raw reading interval, and filter shift.
- [x] All light commands are debug-only (`#ifdef DEBUG_ENABLED`).

### Native Tests
- [x] `MockLightSensor` updated with `readFiltered()`, `setAttenuation()`, `getAttenuation()`, `setFilterShift()`, `getFilterShift()`, `setRawReadingIntervalMs()`, `getRawReadingIntervalMs()`. For deterministic testing, `readFiltered()` bypasses timing and returns the raw value directly.
- [x] New tests:
  - `setAttenuation()` accepts `1.1`, `1.5`, `2.2`, `3.3`; rejects all other values.
  - `setFilterShift()` accepts 1–6; rejects 0 and 7+.
  - `readZone()` and `readState()` use filtered value when `setRaw()` is called (mock `readFiltered()` returns the injected raw).
  - All existing US-0045 tests continue to pass (12 tests).

### Validation
- [x] `pio test -e native` passes with all existing and new tests.
- [x] Debug build compiles successfully.
- [x] Production build compiles successfully (debug CLI commands stripped).

## Notes
- The raw reading interval uses `millis()` and is non-blocking — `readFiltered()` returns immediately without `delay()`.
- `readRaw()` remains available (const, instantaneous) for diagnostics via `light status`.
- Attenuation, filter shift, and raw reading interval NVS persistence is deferred to US-0038.
- The `readFiltered()` seed on first call means the sensor returns a reasonable value immediately at boot rather than ramping from zero over several seconds.
- Pin-specific attenuation means the light sensor ADC pin is the only one affected — WiFi-sensitive ADC2 pins and any future ADC pins are unaffected.
